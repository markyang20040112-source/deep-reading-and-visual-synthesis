# 特化格式 A：視覺化知識圖譜與概念架構圖規範 (Visual Knowledge Diagram Spec)

> [!CAUTION]
> **核心鐵律**：嚴禁使用擴散生圖模型（Imagen/DALL-E）繪製中文字圖表！所有繁體中文知識圖譜必須 100% 由 Python `matplotlib`（搭配 [generate_mindmap.py](../scripts/generate_mindmap.py) 引擎）精確渲染。

---

## 零、 Ausubel-Sweller 認知負荷自動分圖與「宏觀主圖優先」鐵律 `[依據：Ausubel 1968; Sweller 2019]`

1. **禁止將全篇架構、深度技術問答與跨篇整合硬塞入單張圖譜**：當第一階段收斂之知識同時涵蓋「原文完整脈絡」、「深層方法論／數學推導批判」與「跨多篇文章系統合體」時，必須執行 **分段原則（Segmenting Principle）** 自動拆分為 2～4 張獨立高解析度圖譜。
2. **第 1 張圖強制為「本篇文章整體內容架構主圖（Article Master Structure Map）」**：
   - 根據 **Ausubel 前導組織體與宏觀結構理論（Macrostructure Subsumption Theory）**，**編號 `01` 的首張圖譜永遠必須 100% 聚焦於「本篇文章本身的完整內容脈絡與章節邏輯骨架」**（從問題背景／調查現況 $\rightarrow$ 核心分析矩陣 $\rightarrow$ 各大主軸論點與案例 $\rightarrow$ 風險與結論建議），先為讀者建立完整的單篇認知地圖。
   - **編號 `02` 以後的圖譜**，才依序展開「核心概念與機制深度拆解圖」、「方法論限制與破局批判專題圖」以及「跨篇合體終極架構圖」。

## 一、 五大動態拓撲版型選型矩陣 `[依據：Eppler 2006; Novak 2008; Tversky 2011]`

繪圖前必須先根據文章知識結構，從以下 5 種拓撲版型中挑選最匹配的一種（嚴禁將所有文章都畫成單一放射狀心智圖）：

| 拓撲代號與名稱 | 適用知識結構 | 0～100 瑞士網格空間配置規範 |
| :--- | :--- | :--- |
| **T1：焦點問題層級概念圖**<br>*(Top-Down Concept Map)* | 理論推導、學術論文、第一性原理拆解 | • **頂層（Y: 76~86）**：置中「焦點問題與核心定理樞紐」。<br>• **中層（Y: 44~68）**：並排 3～4 張「核心機制卡」，由頂層以帶謂詞膠囊之有向箭頭向下連接。<br>• **底層（Y: 14~38）**：對應之「實證與處方卡」，並以水平虛線標示跨分支連結（Cross-links）。 |
| **T2：因果與演進流程軸**<br>*(Left-to-Right Pipeline)* | 轉型指南、方法論步驟、痛點至處方鏈條 | • **水平 3～4 個垂直欄位（Columns）**：由左至右為 `Col 1 [結構痛點]` $\xrightarrow{\text{成因診斷}}$ `Col 2 [理論/演算法破局]` $\xrightarrow{\text{機制轉換}}$ `Col 3 [階段處方]` $\xrightarrow{\text{價值收斂}}$ `Col 4 [終極護城河]`。<br>• 每欄外包一個 **Palmer 共同區域底色框（Macro Zone）**，內含 2 張垂直堆疊子卡。 |
| **T3：系統動力學雙迴路圖**<br>*(System Dynamics Loop)* | 商業生態、微宏觀經濟循環、雙向反饋、跨篇統整 | • **中央迴路區（X: 34~66）**：配置兩個核心實體（如：下方實線框「核心造血引擎」$\leftrightarrow$ 上方虛線框「外部助燃劑/環境約束」），以弧形有向箭頭連接並標註 `+ 增強 / - 調節` 謂詞膠囊。<br>• **兩側模組區（左 X: 4~30，右 X: 70~96）**：左右各配置共同區域容器，內含 2～3 張卡片連入中央。 |
| **T4：對照矩陣與雙欄架構**<br>*(Comparative / 2x2 Matrix)* | 典範轉移（舊 vs. 新）、人機分工、2×2 象限策略 | • **左右雙大區（左 X: 4~48 vs. 右 X: 52~96）** 或 **中央十字四象限**。<br>• 左區採用 `danger` 警示色條，右區採用 `primary`/`success` 破局色條；中央以雙向對照膠囊橋樑逐層比較。 |
| **T5：瑞士網格核心放射圖**<br>*(Swiss Hub-and-Spoke)* | 單一主題多維度剖析（痛點、理論、盲點、處方、思辨） | • **中央核心樞紐（X: 38~62, Y: 44~58）**：深色高對比核心卡。<br>• **左右對稱卡片（左 X: 4~33，右 X: 67~96）**：左 2～3 卡、右 2 卡（同欄等寬 `W=29`），所有連線附帶關係謂詞膠囊。<br>• **底部全寬收斂橫幅（X: 4~96, Y: 2.5~10.3）**。 |

## 二、 程式級渲染、動態像素行寬與抗破版硬性規則 `[依據：Purchase 1997; Tufte 1990; W3C CLREQ; Bringhurst 2012]`

直接匯入或擴充 [generate_mindmap.py](../scripts/generate_mindmap.py) 內建函數執行：

1. **畫布與無損銳利度參數**：
   - `figsize=(28, 18.5)`（或寬幅 `24x15`）、`dpi=240`、`pil_kwargs={'quality': 98, 'subsampling': 0}`（強制關閉色度抽樣，消除中文字毛邊）。
   - **字型安全與自動淨化（Glyph Sanitization）**：微軟正黑體缺 `U+2794` (`➔`) 與 `U+2194` (`↔`)，繪圖前必須透過 `sanitize_cjk_glyphs()` 自動映射為安全字元 `→` 與 `⇄` / `<->`，**嚴禁出現缺字方框（Tofu box）**。
2. **動態像素行寬換算公式（100% 根絕「框內右側大片空白」與「文字出框」）`[W3C CLREQ & Palmer 1992]`**：
   - **嚴禁寫死過小的固定字數上限（如把寬卡設為 `max_em_width=20` 導致右側空出 40% 白邊）**！
   - 必須呼叫 `compute_dynamic_max_em(card_width, fig_width_in, body_fontsize)`，依卡片在畫布上的實際物理寬度（Points）扣除左右對稱內距後，動態算出精確的 `max_em_width`：
     $$\text{Max\_Em\_Width} = \frac{\left(\frac{W_{\text{card}}}{100} \times \text{Fig\_Width\_In} \times 72\right) - \text{Left\_Right\_Padding\_Pt}}{\text{Font\_Size\_Pt} \times 1.03}$$
     確保每一行文字自然延伸並填滿卡片寬度的 **`88%～92%`**！
   - **CJK 避頭尾點與英文單字不拆字分詞（Token-Aware Wrapping）**：使用正規表達式將英文單字、網址、帶逗號數字（如 `Outset.ai`, `1,000+`）視為不可分割之整體 Token，並遵守 W3C CLREQ 避頭點規則（禁止 `）`、`」`、`】`、`、`、`。` 落於行首）。
3. **Tufte 四層 Z-Order 深度分離與連線膠囊走廊定位 `[Purchase 1997]`**：
   - `zorder = 1`：`draw_macro_zone()` 繪製 Palmer 共同區域極淺底色容器框。
   - `zorder = 2`：`draw_labeled_bezier()` 繪製 **零交叉（Zero Edge Crossings）** 平滑連線。
   - `zorder = 3~4`：`draw_modern_card()` 繪製微陰影、純白/暖白卡面、左側 4pt 語意強調色條、標題膠囊與內文。
   - `zorder = 5`：連接線關係謂詞膠囊標籤**必須精確落於兩張卡片之間的空白走廊中央（或獨立停靠於卡片頂部/底部邊緣外），嚴禁壓在卡片左右側邊框線上造成文字重疊**。

4. **卡片內「水平平行列槽均分法（Modular Row Slots）」與「全形懸掛縮排」`[Müller-Brockmann 1981; W3C Box Alignment; Bringhurst 2012]`**：
   - **廢除將所有列點串成單一字串靠上貼齊的做法（避免「上擠下空」與左右並排卡片列點高低錯位）**：`draw_card()` 必須將卡片扣除標題後的可用垂直高度 `avail_h` 依列點數 $N$ **均分為 $N$ 個獨立的水平列槽（Row Slots）**，每個列點獨立繪製於專屬列槽中心（`va="center"`，行距 `1.56x`），並在列槽間繪製極淺水平輔助分隔線（`#E2E8F0`）。這確保：① 同一水平層級的所有並排卡片，其第 1、2、3 列點在水平層面嚴格平行對齊；② 列點均勻舒展於整張卡片，徹底消除卡片底部大片留白與擁擠感。
   - **全形懸掛縮排（Full-Width Hanging Indent）**：當列點換行時，第 2、3 行開頭必須使用與首行 `"● "` 等寬的全形加半形空白 `"　 "`（`\u3000 `），使多行文字左緣形成筆直切齊的矩形區塊。
5. **中央深色核心方框（Central Hub）與橫幅之「區塊置中、文字靠左」及垂直均分 `[Müller-Brockmann 1981]`**：
   - **禁止對多行 `●` 列點直接使用 `ha="center"`**（避免字數不同時圓點 `●` 左右參差不齊）：`draw_central_hub()` 必須先計算列點區塊的最大字寬，將**區塊整體置中於方框、內部各行文字則統一靠左對齊（`ha="left"`）**，確保所有 `●` 圓點排成筆直垂直線。
   - **消除中央方框中間黑洞留白**：主標題與下方列點必須收攏於方框中央並以細亮線分隔，避免上下文字緊貼邊框而中間空出大片黑洞。

## 三、 產出後強制驗收 (Visual Quality Gate)
執行 Python 腳本生成圖片後，**必須呼叫 `read_file` 檢視生成的圖片檔**，確認：
- [ ] **0 文字穿框或截斷**、**0 框內右側或底部異常大片空白（文字須填滿卡片寬度 88%~92%，垂直列槽均分舒展）**。
- [ ] **並排卡片之各列點在水平層面嚴格平行對齊**、**中央深色方框之 `●` 圓點垂直切齊**、**換行懸掛縮排整齊**。
- [ ] **0 卡片或連線膠囊壓框重疊**、**0 英文單字被腰斬斷行**、**0 連線交叉打結**。
